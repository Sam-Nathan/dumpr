# Dumpr Edge Functions

Deno functions, contract in `docs/architecture.md` §8. Every function is deployed with `verify_jwt = false` and
authenticates in code (`_shared/auth.ts`), so both the legacy anon JWT and `sb_publishable_` keys work as the `apikey`.
Errors use `{ "error": { "code", "message", "details"? } }` (see `_shared/http.ts`), except `send-sms-msg91`, which uses the
Supabase hook shape `{ "error": { "http_code", "message" } }`.

| Function | Method | Auth (in code) | Request | Response |
|---|---|---|---|---|
| `upload-init`, `upload-complete` | POST | user (guests ok) | see architecture §8 | owned by the upload engineer |
| `media-sign` | POST | user, guests ok (`requireUser`) | `{items:[{photo_id, variant: thumb\|display\|original}]}` (1..300) or `{avatar_keys:["a/..."]}` (1..100) | `{urls:{"<photo_id>:<variant>" \| "<avatar_key>": url}, unavailable:{key: "not_found"\|"downloads_disabled"}, expires_at}`; URLs are signed at the top of the hour and live 7 h (>= 6 h left when handed out; identical for the whole hour, `response-cache-control: private, max-age=21600`); originals carry `dumpr-<roll>-<photo_id>.<ext>` as download name |
| `invite-preview` | GET `?code=` | none (anon) | query `code` | `invite_preview` RPC result minus `cover_thumb_key`, plus `cover_url`, `host.avatar_url`, `facepile[].avatar_url` (1 h); `404` with `{status:"not_found",...}` for unknown codes; `Cache-Control: public, max-age=60` |
| `push-dispatch` | POST (`?job=purge` optional) | cron only: header `x-cron-secret` = `CRON_SECRET` | none | push: `{job:"push", claimed, sent, pushes, tokens_removed, marked, retry}`; purge: `{job:"purge", claimed, deleted, failed}` (`503 storage_not_configured` when R2 secrets are missing) |
| `account` | POST | user, guests ok | `{action:"export"}` or `{action:"delete", confirm:"DELETE"}` | export: `{exported_at, profile, crews:[{id,name,role}], photos:[{id,roll_id,roll_name,taken_at,caption,url}], truncated}` (original URLs, 24 h, cap 5000); delete: `{deleted:true, queued_keys}` or `409 last_host` with `details.crews` |
| `send-sms-msg91` | POST | Standard Webhooks signature (`SEND_SMS_HOOK_SECRET`) | Supabase Send SMS hook payload `{user:{phone}, sms:{otp}}` | `200 {}` or `500 {error:{http_code:500, message:"sms_failed"\|"sms_not_configured"}}` |

`media-sign` reads photos with one `photos_by_ids` RPC and avatars (`profiles`) through the caller's RLS client; anything the caller cannot see comes back under
`unavailable` instead of `urls`. `original` additionally needs `rolls.allow_downloads`, unless the caller is the uploader,
the roll creator, or a host/cohost of the crew.

## Secrets

Set with `supabase secrets set NAME=value` (or Dashboard → Edge Functions → Secrets). `SUPABASE_URL`,
`SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are injected automatically.

| Secret | Used by | Notes |
|---|---|---|
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | media-sign, invite-preview, push-dispatch (purge), account, upload-* | missing → `503 storage_not_configured` (invite-preview still answers, without image URLs) |
| `CRON_SECRET` | push-dispatch | same value as the Vault secret `cron_secret` the database sends |
| `SEND_SMS_HOOK_SECRET` | send-sms-msg91 | the `v1,whsec_...` value generated by the Supabase dashboard |
| `MSG91_AUTH_KEY`, `MSG91_TEMPLATE_ID` | send-sms-msg91 | required; missing → `500 sms_not_configured` |
| `MSG91_ANDROID_HASH` | send-sms-msg91 | optional, 11-char app signature hash for SMS Retriever auto-read |
| `MSG91_SENDER_ID` | (DLT/MSG91 template) | documented in §8; the Flow API takes the sender from the template, so the function does not read it |
| `EXPO_ACCESS_TOKEN` | push-dispatch | optional bearer for Expo "enhanced push security" |
| `ALLOWED_ORIGINS` | all | optional comma list, defaults to dumpr.app, www.dumpr.app, localhost:3000 |

## Deploying

```
supabase functions deploy media-sign invite-preview push-dispatch account send-sms-msg91 --no-verify-jwt
```

(`--no-verify-jwt` is required for all of them; the Send SMS hook is called by Auth with a signature, not a user JWT.)

## Cron: push dispatch and purge

`pg_cron` + `pg_net` call the function every minute with the shared secret (architecture §7):

```sql
select cron.schedule('push-dispatch', '* * * * *', $$
  select net.http_post(
    url     := 'https://evxufdovegjrlwpxfmhl.supabase.co/functions/v1/push-dispatch',
    headers := jsonb_build_object('content-type','application/json',
                 'x-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name = 'cron_secret')),
    body    := '{}'::jsonb,
    timeout_milliseconds := 20000);
$$);
-- daily R2 purge (same function, ?job=purge)
select cron.schedule('media-purge', '23 3 * * *', $$
  select net.http_post(
    url     := 'https://evxufdovegjrlwpxfmhl.supabase.co/functions/v1/push-dispatch?job=purge',
    headers := jsonb_build_object('content-type','application/json',
                 'x-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name = 'cron_secret')),
    body    := '{}'::jsonb, timeout_milliseconds := 20000);
$$);
```

Each run claims at most 500 events, stops sending after ~15 s and leaves un-sent events unmarked for the next minute.
Events older than 24 h are marked pushed without sending. A recipient receives at most 3 pushes per run (extra events
collapse into "N more updates on Dumpr").

## Send SMS hook (MSG91)

1. Dashboard → Authentication → Hooks → **Send SMS hook** → type **HTTPS**.
2. URL: `https://evxufdovegjrlwpxfmhl.supabase.co/functions/v1/send-sms-msg91`
3. Click **Generate secret**, copy the `v1,whsec_...` value and store it:
   `supabase secrets set SEND_SMS_HOOK_SECRET='v1,whsec_...'`
4. Also set `MSG91_AUTH_KEY`, `MSG91_TEMPLATE_ID` (and optionally `MSG91_ANDROID_HASH`), enable the hook, and make sure
   Authentication → Providers → Phone is enabled (the provider's own SMS credentials are not used when the hook is on).

The function rejects requests whose `webhook-timestamp` is more than 5 minutes off and never logs the OTP or the full
phone number (only `**NN`, the last two digits).

### MSG91 DLT template requirement

India requires a DLT-registered template. Register one whose body contains the OTP variable, e.g.
`<#> ##otp## is your Dumpr code. It expires in 10 minutes. ##hash##`, create the matching MSG91 **Flow** with variables
`otp` and `hash`, and put its id in `MSG91_TEMPLATE_ID`. The function posts
`{template_id, short_url:"0", recipients:[{mobiles:"<E.164 without +>", otp, hash}]}` to
`https://control.msg91.com/api/v5/flow`. For Android SMS Retriever auto-read the message must start with `<#>` and end
with the 11-character app hash (`MSG91_ANDROID_HASH`; empty string when unset). A non-2xx answer or `type: "error"` from MSG91
becomes `500 sms_failed`, so the user sees a retryable error.

## Database contracts used (service role only unless noted)

`invite_preview(p_code)` (anon + auth), `svc_claim_push_batch(p_limit)`, `svc_mark_pushed(p_ids)`,
`svc_media_purge_claim(p_limit)`, `svc_media_purge_done(p_keys)`, `svc_account_summary(p_user)`.
`push-dispatch` also reads `notification_prefs`, `push_tokens`, `crew_members.muted`, `roll_members.muted`, `profiles`, `crews`, `rolls`
(only when `svc_claim_push_batch` does not already embed `tokens` / `prefs`); `account` inserts into `media_purge_queue(key)`.

## Tests

Run from each function directory (the repo-root `package.json` makes Deno look for `node_modules`; each function's
`deno.json` sets `nodeModulesDir: none`, which only applies from there or with `--config`):

```
cd supabase/functions/<fn> && deno check index.ts && deno test --allow-env . ../_shared
```
